# .96: bounded wants-only runtime cleanup

Base: current main c9c0c5e, after the tooling-only merge of PR #78.
PR #78 did not create a runtime release or deploy Pages.

## Dependency Evidence

- Acorn top-level function analysis identified the retired inventory editor,
  bulk controls, autocomplete, browse context, and sorting cluster. Every removed
  function name was checked against all runtime JavaScript and index.html outside
  that cluster. There were no external callers, including inline-handler strings.
- The inventory HTML and renderMyHave/renderHaveBrowse implementations were already
  absent. Delete their remaining callers and timers, not replacement wrappers.
- backgroundCatalogDomain/backgroundVisualDomain had only startup declarations
  and assertions, with no method calls. Remove both modules from the HTML loader,
  signed-out deferred loader, service-worker cache, and reviewed Pages inventory.
- Background picker and artwork CSS selectors had no runtime markup producers.
  Remove them and the stale locale-change picker hook. Compact public-share label
  styling remains because existing links still use it.

## Deletions

- 36 application functions: inventory editing, quantity/mode/gender operations,
  bulk operations, duplicate inventory search, browse models, and renderer queues.
- Two background runtime modules, their runtime generator, and unused picker/art
  styling. No image files were deleted: the retired artwork registry was empty.
- Seven obsolete test cases: three background presentation tests, two picker/row
  tests, and two browser-catalog search tests. One absence regression replaces them
  (net six fewer cases). Existing session tests lose retired inventory state and
  gain the current wants-selection fixture they were missing.

## Deliberately Retained

- Stored Have/FT/offers, legacy sync queues, qualifier codecs, and record parsers.
  No migrations, purges, writes, identity changes, or schema changes are introduced.
- Existing schedule/history reconciliation and its read-only inventory guard:
  scheduler cancellation and accepted historical records still reference it.
  Deleting that connected path would require a separate behavioral decision.
- tradeListComparison: despite its old name, Groups, Favorites, Who wants this?,
  wants comparison, and declaration aggregation actively call it.
- Shared sprite lookup, wants search-string builders, Board/share LF handling,
  public v1/v2 decoding, priority handling, and unsupported-costume honesty.
- Archived background metadata and offline provenance checks; these are not shipped.
  Appearance wallpaper settings are separate from Pokemon background qualifiers
  and are outside this bounded pass.
- Provider rollout, PR #63, identity/PIN/recovery66, and backend controls unchanged.

## Measurement And Release

Before release-marker changes: 147,399 fewer raw bytes across application JS,
background modules, and CSS; 20,732 fewer bytes when those files are gzip-compressed
individually. Two fewer first-party script loads (87 to 85); reviewed artifact
inventory shrinks from 560 to 558 files. No claim of measured user-latency gain.

Runtime .96 requires a focused PR, successful affected checks and existing
performance/release gates, then a separately reviewed dispatcher-only repin to
the new immutable allowlist control before the normal manual Pages release.
No deployment is triggered by the merge or tags alone.
