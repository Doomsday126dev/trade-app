# Catalogue .156 read-contract review

The runtime based on live .155 changes the migration reader's returned catalogue adapter from `accountSyncCatalogIdentity` to `accountSyncLegacyCatalogIdentity`. The latter preserves an explicitly stored catalog ID and, for old name-only records, resolves a reviewed legacy ID before using the existing identity lookup. The index retains former IDs alongside canonical new selections. This supports picker deduplication without rewriting or deleting saved records.

Replacing only that adapter expression recreates the previously reviewed handler token hash `47362d8f67a5afae6330665c71f7cf18c197c71ace8146181cdc2a5a2aecdb0f`. The new exact hash is `8ebcda51428eb247434f7f5d762c0fae8534ec29032cfbc9ac63a1aed927fce2`. The token-level regression proves no other changes within `accountSyncReadLegacySources`: the five exact owner paths, eight-second read deadline, captured session/generation checks, reverse UID binding and retained snapshots are unchanged. This does not activate adoption, introduce an account rewrite, add a Firebase call, change Rules or enable a provider.

The local proposal `9c494c9e` adds that exact signature to the runtime's test metadata. The shipped frontend excludes `firebaseReadRegistry.js`. The protected control intentionally narrows promotion: it creates a release-specific contract for exact runtime `c3b6e35c434aeedb632865472077eafd6c0e4d31` and requires only the new signature there. Existing .155 and historical contract objects remain unchanged. A dedicated regression changes an archived .155 fixture to the new adapter and verifies rejection. The new .156 fixture rejects both a reverted adapter and a private-path substitution. No wildcard, checker suppression, original-expiry extension, read-budget increase or new permission is included.

The original IDs and separate normal/Shiny requests are exercised through IndexedDB save, edit and reload in `catalogue-finite-queue.spec.js`; the complete read-contract suite passes all 102 cases locally. Historical sources retain their existing validation tests. Promotion remains reviewable in this control PR; local metadata alone does not change the deployed app or grant access.
